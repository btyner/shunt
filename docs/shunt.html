1. Introduction

shunt is an extension for OMP. It is a port of Spotify's shunt plugin for Claude Code (Apache-2.0). The original sent work to Spotify's internal AiKA service through the Portal CLI. This version needs neither: it sends delegated work to whatever cheaper model OMP is already logged in to, such as Claude Haiku.

The idea is simple. Your main model (for example Opus) is the most capable and the most expensive model you run, and anything that enters its context window is paid for again on every later turn. Reading a 1,000-line file or writing 150 lines of test boilerplate is mostly mechanical work, so it doesn't need that model. shunt hands those jobs to a cheaper worker model and returns only the result: a concise answer, or a one-line "wrote the file" receipt.

shunt adds three things to OMP:

  • A gate: a hook that blocks full-file reads of large files and points the agent to a cheaper path.
  • bulk_read: a tool that asks a cheap model a question about files and returns only the answer.
  • code_write: a tool that has a cheap model generate a file from a spec and reference files, writes it to disk, and returns a receipt.

2. Installation

Requirements

  • OMP installed and logged in to at least one model provider.
  • A cheaper model available to OMP (recommended: anthropic/claude-haiku-4-5).

Install the plugin

Link the plugin directory so OMP loads it in every session:

omp plugin link /path/to/shunt

Or load it for one session only:

omp -e /path/to/shunt

Point the worker at a cheap model

shunt uses OMP's smol model role by default. Assign it in ~/.omp/agent/config.yml: 

modelRoles:
  default: anthropic/claude-opus-5-5
  smol: anthropic/claude-haiku-4-5:low
If smol is unset, it falls back to your default model. shunt then shows a warning at startup: you still save context, but the worker runs on your expensive model and you lose the per-token savings.

Optional settings

Environment variableDefaultPurpose
SHUNT_MIN_LINES350Files longer than this are blocked from full reads.
SHUNT_MODEL@smolWorker model or role alias. A mode's own model: setting overrides it.
SHUNT_TIMEOUT_SECONDS180Time limit for one worker call.

Check that it works

cd /path/to/shunt
SHUNT_MIN_LINES=50 omp -e .

Ask: "Read src/index.ts in full and explain it." The read is blocked and the agent calls bulk_read instead. The result ends with a footer like: 

[shunt: bulk-reader via anthropic/claude-haiku-4-5 · 5373 in / 412 out tokens · $0.0074]

(The token counts and price above are illustrative.)

3. Where the tokens go

An agent conversation is cumulative. Each turn re-sends the whole conversation so far, including every file the agent has read and every piece of code it has written. Prompt caching lowers the price of those repeated tokens, but they still take up context space and still count, and they stay there until compaction.

Two habits get expensive quickly:

  1. Reading whole large files to answer a narrow question. The agent reads a 600-line file to learn what it exports. The answer takes 15 lines, but the other 585 sit in context for the rest of the session.
  2. Writing boilerplate on the most expensive model. Output tokens cost the most, and a large model writing 150 lines of predictable tests pays premium rates for mechanical work. That code then stays in context too.
Rule of thumb: a token that enters the main context costs main-model rates once, and then again (at cache rates) on every later turn. A token that only the worker sees costs worker rates once.

4. How shunt saves tokens

Main agent (Opus)→ asks question / spec → shunt tool→ files + prompt → Worker (Haiku)→ answer / file → Main agent sees only the summary

The savings come from three separate effects:

EffectWhat happensWhy it saves
Context isolationFile contents go to the worker and never enter the main conversation.The main model doesn't re-read those tokens on later turns.
Cheaper per-token priceThe worker is a smaller model.Reading and generation are billed at the smaller model's rates.
Small resultsOnly a concise answer or a one-line receipt comes back.The main context grows by a few lines instead of hundreds.

Stateless one-shot calls

Each worker call is independent: one request and one response, with no conversation history. To follow up, the agent calls again with the same files. This sounds wasteful, but the re-sent files cost the cheap worker, not the main agent's context.

5. Layer 1: the gate

On its own, an agent's habit is to read whole files, and an instruction to "please delegate" is often ignored. So shunt uses a hook that inspects every read and bash call before it runs. A full-file dump of a large text file is blocked, and the block message tells the agent what to do instead. 

shunt: websocket-handler.ts is 602 lines (threshold 350). Don't pull it into context whole.
To understand or summarize it, call bulk_read with your question and the paths — only the
answer comes back. If you need exact text to edit, read only the range you need, e.g.
websocket-handler.ts:1-200.

What is blocked and what is allowed

CallAllowedBlocked
read Line ranges (f:1-200, f:-60), small files, binary or missing files, URLs, directories A bare path (or bare :raw) to a text file over the threshold
bash Anything piped or redirected (cat f | grep x), head/tail printing few lines, non-reading commands cat, less, more over the threshold; head/tail printing more than the threshold

Reading a line range is always allowed. An agent that needs exact text to make an edit can still get it, but only the part it needs.

6. Layer 2: bulk_read

bulk_read takes a question and a list of paths. The worker reads the files and answers with structured bullets. Only that answer returns to the main agent.

Without shunt

The main agent reads a 602-line file. All 602 lines enter context and are re-sent on every later turn.

With shunt

Haiku reads the 602 lines once at its lower price. About 20 lines of answer enter the main context.

Good uses: understanding large files, questions that span 3 or more files, summarizing long diffs or logs.

Verify before editing: worker answers are summaries. When the agent needs an exact line number or value for an edit, it should confirm it with a ranged read.

7. Layer 3: code_write

code_write takes a spec, a list of reference files, and an optional target path. The worker generates the code following the patterns in the references. If a target is given, the code is written straight to disk and the main agent receives only: 

Wrote user-service.test.ts (141 lines). Review it with ranged reads.
[shunt: code-writer via anthropic/claude-haiku-4-5 · … tokens · $0.0070]

That saves twice:

  1. The expensive model never generates the code. Output tokens are the priciest kind, and they are now billed at the worker's rate.
  2. The code never enters the main conversation. The main agent can spot-check it with ranged reads instead of carrying all of it.
If the main agent reads the whole generated file back afterwards, the second saving is lost (the first one remains). Spot-checks with ranged reads keep both.

Typical uses: unit tests that follow an existing test, fixtures and mock data, config files, type stubs, docstrings, and new routes, handlers or migrations that copy an existing pattern.

Safeguards: references is required, so the worker always has a pattern to match. Output cut off at the worker's length limit is never written to disk.

8. Choosing the worker model

The worker model is chosen in this order, first match wins:

  1. The model: line in the mode file being used
  2. The SHUNT_MODEL environment variable
  3. OMP's @smol role

A layout of OMP model roles that fits shunt well:

modelRoles:
  default: anthropic/claude-opus-5-5          # main conversation
  slow:    anthropic/claude-opus-5-5:medium   # deep reasoning, advisor
  plan:    "@slow"                            # plan mode
  task:    anthropic/claude-sonnet-5-5:medium # subagents
  smol:    anthropic/claude-haiku-4-5:low     # shunt worker, cheap side jobs
  commit:  anthropic/claude-haiku-4-5:off     # commit messages
  vision:  anthropic/claude-sonnet-5-5:low    # image questions

shunt doesn't send a thinking level with its worker calls, so the :low on smol only affects OMP's other uses of that role.

9. API key vs. Claude subscription

API keyClaude subscription
What you saveDollars per tokenUsage-limit headroom
The $ in the footerClose to what you are actually billedA rough measure of usage, not a charge
Biggest benefitCheaper worker rates plus a smaller contextFewer Opus tokens, so your Opus allowance lasts longer

With a subscription, every call is counted against the same login: main turns, subagents, and shunt's worker calls. Moving bulk reading and boilerplate from Opus to Haiku stretches your limits much further.

10. Custom modes

A mode is a named worker system prompt, with an optional model and temperature. Modes are what make shunt useful for other workflows beyond code. There are two built-ins, bulk-reader and code-writer. Add your own as markdown files; project modes override user modes, which override built-ins: 

<project>/.omp/shunt/modes/<name>.md
~/.omp/agent/shunt/modes/<name>.md
---
model: anthropic/claude-haiku-4-5   # optional
temperature: 0.1                    # optional
---
You triage application logs. Answer with timestamps and error codes only.

Use one by name: bulk_read with mode: "log-triage". An unknown name fails and lists the available modes.

Prompt caching

Prompt caching is off for worker calls. Because the question comes after the files, a follow-up with a new question would never reuse the cached entry, and writing to the cache adds a premium. In testing, the same call cost $0.0305 with caching and $0.0148 without.

11. When not to delegate

Keep these with the main agent:

  • Debugging: needs exact text and careful reasoning.
  • Editing existing code: use ranged reads and precise edits.
  • Small files: the tool call and review cost more than they save.
  • Architecture and design decisions: need your strongest model.
  • New logic with no file to copy from: code_write depends on reference files.

12. Limitations

  • Only read and bash are gated. Reads through the eval tool are not blocked.
  • A ranged read of any size is allowed through, the same as in the original plugin.
  • One worker call is limited by the worker model's context window. Split very large batches.
  • The main agent decides when to use bulk_read and code_write, and it doesn't weigh cost. Ask for them directly, or add standing guidance to an AGENTS.md file.
